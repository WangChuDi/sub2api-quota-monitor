# 监控算法说明

## 采样频率

服务保存每次采集得到的主账号、Spark 账号 quota/usage 快照。默认间隔为 300 秒；每次采集都会把本次累计使用量与上次累计使用量相减，再按上一次真实采样间隔归一化到 300 秒。

当归一化后的金额增量达到 `FAST_USAGE_AMOUNT_THRESHOLD`，或请求数增量达到 `FAST_USAGE_REQUEST_THRESHOLD` 时，进入 60 秒高频模式。高频模式持续 `FAST_HOLD_SECONDS`，期间再次出现大增量会延长保持时间。采样频率本身不会被当作消耗速度。

## 斜率拟合

只使用主账号的 `(已用百分比, 使用额度)` 数据。因为上游百分比是整数，程序先把同一百分比的多条金额取中位数，再对相邻百分比做三点中位数平滑。之后使用普通最小二乘回归：

```text
使用额度 = 截距 + 斜率 * 已用百分比
```

斜率单位是“每 1 个百分点对应的使用额度”。变点检测会递归切分序列，并分别拟合切分点两侧的斜率。只有同时满足最小样本数、相对变化阈值和多重比较校正后的显著性条件，才会保留为变点。

## 预计用完

推算总额度使用当前有效回归段的斜率。预计用完时间不再从整数百分比的跳变速度推算，而是：

```text
剩余金额 = 推算总额度 - 当前使用额度
金额消耗速度 = 多个采样跨度的正向金额增量 / 时间增量的中位数
预计用完 = 最新采样时间 + 剩余金额 / 金额消耗速度
```

没有足够的正向金额速度时，服务退回上游提供的 reset 时间。

## Bark 触发

服务启动后先发送一次“额度监控已启动”通知，以验证 Bark 配置和网络连接。随后第一次扫描当前历史变点只建立基线；只有后续出现新的变点指纹时才发送“额度斜率拐点”通知。通知去重和待发送状态只保存在当前进程内，容器重启会重新建立基线，不会重播旧历史。
